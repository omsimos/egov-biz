# System Architecture — Omsimos eGov Platform

*Grounded in the repository as of 2026-07-21. This document describes what is actually implemented in code; the concept, feasibility, and impact case lives in [`research-paper.md`](./research-paper.md).*

---

## 1. Overview

The repository is a **Bun + Turborepo monorepo** with two reusable packages and two sample apps:

```
egov-scripts/
├── packages/
│   ├── egov/                 # Typed client SDK for eGovPH partner APIs (9 services)
│   └── transcript-scraper/   # YouTube timestamped-transcript extractor (TypeScript)
├── apps/
│   ├── egov-smoke/           # Live smoke harness that exercises the eGov services
│   └── egov-sso-sample/      # Reference SSO login flow (server + client)
├── docs/                     # This document + research paper
├── turbo.json                # Turborepo task graph
└── .env.sample               # All service base URLs + credential slots
```

Two building blocks underpin the product: the **transcript-scraper** (turns a hearing video into timestamped text) and the **egov SDK** (typed access to the eGovPH services the platform composes). Neither is the product itself — they are the verified foundation the product is built on.

---

## 2. Package: `transcript-scraper`

A dependency-free TypeScript module (`packages/transcript-scraper/src/api.ts`) that extracts a YouTube video's public transcript.

- **Entry point:** `getYouTubeTranscript(input, options)` (aliased `extractTranscript`). Accepts a URL or bare 11-char video ID (`parseYouTubeVideoId` handles `watch?v=`, `youtu.be`, `/embed`, `/live`, `/shorts`).
- **How it works:** fetches the watch page, extracts the embedded `ytInitialData` / `ytInitialPlayerResponse` JSON via brace-balanced parsing, reads `INNERTUBE_API_KEY` and `INNERTUBE_CLIENT_VERSION`, then POSTs to YouTube's internal `youtubei/v1/get_panel` endpoint to retrieve transcript segments.
- **Output (`TranscriptResult`):** `segments[]` (each `{ start, text, timestamp }`), `srt` (generated via `segmentsToSrt`), `autogenerated` (true when the selected caption track `kind === "asr"`), `languageCode`, `durationSeconds`, `title`, `trackName`, `videoId`, `watchUrl`.
- **Constraints (in code):** depends on the undocumented `get_panel` endpoint; throws on unavailable/transcript-free videos; selects the ASR track when present (so Filipino auto-captions come through with their known quality limits).

This confirms the transcription layer end-to-end: a hearing URL yields **timestamped** segments with a language code and an auto-generated flag — exactly the input the refinement and fact-check stages need.

## 3. Package: `egov` — the eGovPH SDK

A typed, tree-shakeable SDK (`packages/egov/src`) exposing **9 eGovPH services** as independent submodule exports. A shared `core/` provides:

- `client.ts` — `createEgovTransport()`, a thin `fetch` wrapper (URL/query building, JSON/raw bodies, `Accept: application/json`, error normalization to `EgovApiError`).
- `env.ts` — typed environment resolution (`requireEgovEnvironment`) over Bun/Node env; the union `EgovEnvironmentName` enumerates every credential the SDK reads.
- `catalog.ts` — a self-describing endpoint catalog (`defineEgovCatalog`) so each service documents its own endpoints, methods, params, and responses.
- Every service ships `create(...)` (explicit config) and `fromEnv(...)` (reads credentials from env), plus unit tests under `packages/egov/test/`.

### 3.2 eGov AI — the detail that matters most

`packages/egov/src/eGovAi/api.ts` implements a **credit-metered, token-based** service:

1. `generateAccessToken(accessCode)` → `{ access_token, credits_total, credits_remaining, expires_in_seconds }`. All subsequent calls send `Authorization: Bearer <access_token>`.
2. Generation endpoints take `{ prompt, category }` and return `{ data, session_id }`: **`ai_assistant`** (general conversational generation — the LLM the refinement/summarization layer uses), `laws_and_regulations`, `speech_maker`, `tourism`.
3. **`translator`** takes `{ prompt, source_lang, target_lang }` (ISO-639 codes) and returns `{ translated_prompt, transliterated_prompt, ... }`.
4. **`document_extractor`** takes a multipart file (`Blob`) and returns extracted text — usable for bill PDFs, COA reports, GAA documents.
5. `getTokenCredits()` → `{ credits_used, credits_remaining, credits_total, expires_at }`.

**Key facts for the product and the paper:**
- The **refinement middleware is real and grounded**: repair/summarization → `ai_assistant`; translation → `translator`. These are the actual endpoints, not an assumption.
- **There is no speech-to-text.** `speech_maker` is generation (TTS-style), not transcription. YouTube captions remain the transcription source.
- **Credits are a hard, metered cost.** Every AI call draws down a finite team credit balance tied to a short-lived token. This is the dominant cost and quota constraint, and it must shape batching/caching decisions.
- **Filipino/Taglish quality is still unverified in code** — the SDK exposes the endpoints but nothing documents language quality; validate empirically against real hearing captions.

### 3.3 eGov Compass — authenticated budget data

`packages/egov/src/eGovCompass/*` is an **authenticated partner client** (`dbm-ws.oueg.info`, `EGOVCOMPASS_API_KEY`) — distinct from, and stronger than, the public undocumented `compass-api.dbm.gov.ph`. It returns structured, typed budget data:

- **SAAODB records + dashboard:** the full appropriations → allotments → obligations → disbursements cascade, with `unobligated`/`unreleased`, obligation/disbursement **rates**, expense-class breakdown (`PS`/`MOOE`/`CO`/`FINEX`), and top entities. Queryable by `reportYear`, `period` (`FY`/`Q1`–`Q4`), `sheetScope` (`agency`/`sucs`/`summary`), and entity.
- **SARO** records (release orders, by dept/agency/expense-class/SARO number), **NCA** records (cash allocations), **LGSF** records + dashboard (local government support fund, by region/province/municipality/program).

For budget claims made in a hearing, this yields precise, structured figures to compare against — and it powers the platform's budget views directly. The smoke harness queries it with `reportYear = current year`, so it is not hard-pinned to a single fiscal year in code.

### 3.4 eGovChain, eMessage, and the rest

- **eGovChain** (`packages/egov/src/eGovChain`) is an **EVM-compatible JSON-RPC client** (`eth_*` methods, no auth in the smoke run). Anchoring a transcript/verdict hash means submitting a transaction via `sendRawTransaction`; verification reads it back. This is the mechanism behind the optional tamper-evidence feature.
- **eMessage** implements **SMS push only** in code (the catalog blurb mentions email/in-app, but only `sendSms` is wired). Sufficient for calendar/fact-check alerts.
- **eReport** is a full citizen-complaint workflow (OTP-gated) with PSGC location lookups — the basis for an optional "flag misinformation" feature.
- **eGov SSO** is an OAuth-style citizen login returning a rich profile (national ID, passport, educational attainment) — the cleanest path to verified accounts if ever needed. **eVerify / eGovPay / Face Liveness** belong to identity/payment/biometric products and are out of scope for a public transparency tool.

## 4. How the pieces compose into the product

```
                         ┌─────────────────────────────────────────┐
 YouTube hearing URL ──► │ transcript-scraper                        │
                         │  → segments[] (start,text,timestamp), srt │
                         └───────────────┬───────────────────────────┘
                                         ▼
                         ┌─────────────────────────────────────────┐
                         │ Refinement middleware  (Omsimos)          │
                         │  eGov AI: ai_assistant (repair/summarize) │
                         │           translator (FIL↔EN)             │
                         │  + confidence flagging (our logic)        │
                         └───────────────┬───────────────────────────┘
                                         ▼
                         ┌─────────────────────────────────────────┐
                         │ Orchestrator (eve)                        │
                         │  routes each claim to a specialized       │
                         │  subagent, then aggregates verdicts       │
                         │  ┌─────────────────────────────────────┐  │
                         │  │ eGov AI subagent (own endpoint)      │  │
                         │  │ BetterGov + Juris subagent (MCP)     │  │
                         │  │ Compass budget subagent (SDK)        │  │
                         │  │ Web-search subagent (trusted allow-  │  │
                         │  │   list, corroboration only)          │  │
                         │  └─────────────────────────────────────┘  │
                         └───────────────┬───────────────────────────┘
                                         ▼
                         ┌─────────────────────────────────────────┐
                         │ Fact-checker (aggregation)                │
                         │  claim → verdict → cited source → excerpt │
                         └───────────────┬───────────────────────────┘
                                         ▼
             ┌───────────────────────────────────────────────────────────┐
             │ Surfaces & side-effects                                     │
             │  • Views: agenda calendar, legislative-data explorer        │
             │  • eMessage: SMS alerts   • eGovChain: optional hash anchor │
             └───────────────────────────────────────────────────────────┘
```

Data-source ownership by claim type: **legislative status** → BetterGov Open Congress API; **legal claim** → Juris.ph MCP; **budget figure** → **eGov Compass** (authenticated, via the SDK). eGov AI is the text-processing layer, not a data source; trusted-source web search corroborates but never grounds a verdict alone.

### 4.1 Multi-agent orchestration (eve)

The agent layer is not one monolithic prompt but a set of **specialized subagents**, each owning one source and its access protocol, coordinated by an orchestrator built with **eve** (the team's agent framework):

- **eGov AI subagent** — talks to the eGov AI endpoint (token + `ai_assistant`/`translator`/`document_extractor`); handles transcript repair, translation, summarization, and OCR.
- **BetterGov + Juris subagent** — has **direct MCP access** to Juris.ph (`search_jurisprudence`/`get_case`, `search_republic_acts`/`get_republic_act`) and to BetterGov Open Congress for legislative records.
- **Compass budget subagent** — uses the typed Compass SDK (SARO/NCA/SAAODB/LGSF) for budget figures.
- **Web-search subagent** — restricted to the trusted-source allowlist; corroboration only.

The orchestrator classifies each extracted claim, dispatches it to the subagent that owns the authoritative source, and aggregates the returned evidence into the `claim → verdict → cited source → backing excerpt` result. Isolating each source in its own subagent keeps tools/credentials scoped, lets a source's access protocol (REST, MCP, SDK) stay encapsulated, and makes it cheap to add or swap a source without touching the others.

## 5. Configuration, testing, and maturity

- **Config:** every service base URL and credential slot is declared in `.env.sample`; the SDK fails fast via `requireEgovEnvironment` when a credential is missing.
- **Unit tests:** `packages/egov/test/` has a spec per service (`egov-ai`, `compass`, `emessage`, `egov-chain`, `everify`, `ereport`, `egov-sso`, `egov-pay`, `face-liveness`) plus `client` and `env`, and `transcript-scraper` has its own test.
- **Live smoke harness** (`apps/egov-smoke`): performs real calls against **eGov AI, eVerify, eReport, eGov Compass, and eGovChain** (e.g. AI issues a token and reads credits; Compass fetches a SAAODB page; Chain reads chain ID + block). It **deliberately skips** eGov SSO, eMessage, eGovPay, and Face Liveness because their only operations cause real side effects (send an SMS, create a payment, start a liveness session). This is strong feasibility evidence: the integration is wired and exercised, not theoretical.

The typed SDK + per-service tests + live smoke harness indicate the eGov integration is engineered, not speculative — the platform can be assembled on a foundation that already talks to the real services.

## 6. Gaps between foundation and product

The building blocks exist; the product layer is not yet in this repo. To assemble it:

1. **Refinement middleware** — wire `ai_assistant` + `translator` over transcript segments, add confidence flagging, and **cache aggressively** to respect eGov AI credits.
2. **Multi-agent layer (eve) + fact-checker** — not yet present; build the specialized subagents (eGov AI, BetterGov+Juris MCP, Compass SDK, web-search) and the eve orchestrator that routes claims and aggregates verdicts (§4.1).
3. **Views** — agenda calendar (schedule scraped from `congress.gov.ph/committees/committee-meetings`, joined to BetterGov committee data) and the legislative-data explorer (BetterGov API).
4. **Productionization** — move off `hackathon-*`/`*.oueg.info` staging hosts; add credit monitoring (`getTokenCredits`) and adapter-level retries for the undocumented endpoints (YouTube `get_panel`).
